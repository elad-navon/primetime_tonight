# פריים טיים – אפליקציית אנדרואיד

עטיפת [Capacitor](https://capacitorjs.com) לאתר, עם תזכורות לפני שידורים.
המזהה: `com.eladnavon.primetime`, השם: "פריים טיים". מופצת כ-APK חתום
(למשל בוואטסאפ), לא בחנות.

## איך זה בנוי

- **האפליקציה טוענת את האתר החי** (`server.url` ב-`capacitor.config.json`):
  `https://elad-navon.github.io/primetime_tonight/`. כל שינוי באתר מגיע אליה
  בפרסום הרגיל של האתר (דחיפה ל-`main`), בלי APK חדש.
- **בתוך ה-APK** יש רק דף שגיאה (`android-shell/index.html`, `server.errorPath`),
  שמוצג כשהאתר לא נגיש.
- **התזכורות הן קוד של האתר** (`../native/`), שנטען **רק בתוך האפליקציה**
  (`Capacitor.isNativePlatform()` בסוף `index.html`). בדפדפן לא מופיעים
  פעמונים או הגדרות, ושום דבר מ-`native/` לא נטען.
  - `native/reminders-core.js` – הלוגיקה הטהורה: מזהים, התאמה למילים, מה
    לתזמן ומה לבטל. נבדקת ב-`tests/`.
  - `native/app.js` – הפעמונים, חלון ההגדרות, הסריקה והחיבור לתוסף.
  - `native/vendor/capacitor.js` – ה-API הרשמי של `@capacitor/core`
    ו-`@capacitor/local-notifications`, ארוז בקובץ אחד (`npm run build:native`).
    האתר עצמו נשאר בלי שלב בנייה.
- **הטקסט** מוצג ב-100% (`MainActivity.java`) גם כשהגופן בטלפון מוגדל.

## התזכורות

- **פעמון** ליד כל שידור שעוד לא התחיל: לחיצה קובעת תזכורת, לחיצה נוספת מבטלת.
- **מתי**: בתחילת השידור או 5/10/15 דקות לפני (ברירת מחדל: 10). שינוי ההגדרה
  מזיז גם את התזכורות שכבר נקבעו.
- **מילים** ("מכבי תל אביב + כדורסל"): כל שידור שהשם או התיאור שלו כוללים את
  כל המילים מקבל תזכורת. "תל אביב" מוצא גם ת"א (וכך גם ב"ש, פ"ת ועוד), מילה
  שלמה בלבד, עם אות שימוש אחת לפניה. אפשרויות: בלי שידורים חוזרים (ברירת
  מחדל), רק שידורים ישירים ("ישיר!" – משאיר בחוץ למשל משחקי ארכיון).
- **הסריקה** רצה כשהאפליקציה נפתחת וכשחוזרים אליה (לכל היותר פעם ב-20 דקות,
  ומיד אחרי שינוי כלל): 9 ערוצים × 7 ימים מה-API של yes, דרך `fetchChannel`
  של הדף.
- **מגבלה**: כשהאפליקציה סגורה אין סריקה, אז שידור שנוסף ללוח בינתיים יימצא
  רק בפתיחה הבאה. תזכורות שכבר נקבעו מגיעות גם כשהאפליקציה סגורה, וגם אחרי
  הפעלה מחדש של הטלפון (התוסף מתזמן אותן מחדש).

### מזהים ותיאום

- **מזהה ההתראה** הוא מזהה השידור של yes (`item.id`, מספר שלם קטן מ-2³¹), שנשאר
  גם כשהשעה משתנה. בלי מזהה: גיבוב של הערוץ ושעת ההתחלה.
- **מקור האמת** הוא רשימת ההתראות הממתינות של התוסף (`getPending`). לכל אחת
  `extra.kind`: `manual` (פעמון) או `auto` (מילים, עם רשימת הכללים שהתאימו).
- **בכל סריקה**:
  - שידור שמתאים לכמה כללים מקבל תזכורת אחת שמציינת את כולם.
  - תזכורת ידנית לא נוגעים בה, והיא מונעת תזכורת אוטומטית כפולה לאותו שידור.
  - שידור ששעתו השתנתה – התזכורת זזה (אותו מזהה).
  - תזכורת אוטומטית מבוטלת רק כשהסריקה **הוכיחה** שהיא מיותרת: כל הכללים
    שלה נמחקו, או שהערוץ והיום שלה נטענו בהצלחה והשידור כבר לא שם/לא מתאים.
    ערוץ או יום שנכשלו בטעינה לא מבטלים כלום.
  - תזכורת אוטומטית שביטלת לא חוזרת (נשמרת ברשימת "dismissed").
  - לכל היותר 60 תזכורות אוטומטיות, הקרובות ביותר.
- **ההגדרות** (כללים, זמן, אפשרויות) ב-`localStorage` של האפליקציה
  (`pt-reminders-v1`); הגדרות פגומות או חסרות חוזרות לברירת המחדל.

### הרשאות

- `POST_NOTIFICATIONS` (אנדרואיד 13+) – נשאלת בפעם הראשונה שקובעים תזכורת או
  מוסיפים כלל. כבויה: הודעה שמסבירה איך להפעיל.
- **תזמון מדויק** (`SCHEDULE_EXACT_ALARM`, מגיע מהתוסף): עד אנדרואיד 11 תמיד
  מותר. מאנדרואיד 12/14 ייתכן שלא – אז התזכורות נקבעות בלי דיוק (עלולות
  להגיע באיחור של כמה דקות), וחלון ההגדרות מציג "לא פעיל" עם כפתור "לאפשר"
  שפותח את ההגדרה. לא מבקשים תזמון מדויק בלי הרשאה, כי אז התוסף היה פותח את
  מסך ההגדרות בכל תזמון. אין `USE_EXACT_ALARM`.
- לחיצה על תזכורת פותחת את האפליקציה ומציגה איזה שידור זה; אם הוא היום,
  הכרטיס של הערוץ נגלל למרכז.

## פקודות (מתוך `android-app/`)

| פקודה | תפקיד |
|---|---|
| `npm install` | התקנת החבילות (נעולות) |
| `npm test` | בדיקות הלוגיקה, על נתונים אמיתיים מ-yes (`tests/fixtures/`) |
| `npm run test:browser` | האתר בדפדפן (Playwright): בלי תזכורות בדפדפן רגיל; פעמונים וכללים עם תוסף מדומה |
| `npm run build:native` | בניית `../native/vendor/capacitor.js` מחדש (אחרי עדכון החבילות) |
| `npm run icons` | כל האייקונים (האתר והאפליקציה) מציור אחד |
| `npm run android:debug` | בניית ניסיון, מותקנת כ-`com.eladnavon.primetime.dev` לצד האמיתית |
| `npm run android:dev` | בניית ניסיון שטוענת את האתר מהמחשב: `npm run serve` + `adb reverse tcp:8099 tcp:8099` |
| `npm run android:release` | בדיקות, בדיקת `native/vendor`, `cap sync`, בנייה חתומה, בדיקת חתימה/מזהה/גרסה → `release/primetime.apk` |

דורש Java 21 ו-Android SDK עם `build-tools;36.0.0` (`JAVA_HOME` / `ANDROID_HOME`, או
מיקומי ברירת המחדל), ומחוץ למאגר, ב-`C:\Elad\keys\`:

- `primetime-release.jks` – מפתח החתימה. כל עדכון חייב להיות חתום בו.
- `primetime-keystore.properties` – ההגדרות והסיסמה.
- `primetime-version.json` – מונה הגרסאות; כל בנייה מוצלחת מעלה אותו באחד.

**לגבות את שלושתם** יחד עם שאר `C:\Elad\keys\`. בלי המפתח והסיסמה אי אפשר
לעדכן את האפליקציה המותקנת.

## התקנה ועדכון

שולחים את `release/primetime.apk` לעצמך כ"מסמך" ופותחים בטלפון (או
`adb install -r release/primetime.apk`). עדכון: APK חדש מעל הקודם – התזכורות
וההגדרות נשמרות.

**APK חדש צריך רק** לשינויים ב-`android/`, `android-shell/`,
`capacitor.config.json`, באייקון של האפליקציה או בגרסת התוסף. שינוי ב-`native/`
או בכל שאר האתר מגיע בפרסום של האתר.
